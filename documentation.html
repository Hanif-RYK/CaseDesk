CaseDesk documentation

CaseDesk is a legal case management dashboard template for law firms, attorneys, advocates and legal consultants: cases, clients, hearings, a calendar and cause list, documents, tasks, time, invoices, team and reports. It is made with plain HTML, CSS and vanilla JavaScript. There is nothing to install and no build step. You can use it as the front end of your own Laravel, PHP, Node, Django or SaaS project. Version 1.0.0.

Getting started

  1. Unzip the download and open the CaseDesk folder.
  2. Double-click index.html. Everything works offline, without a server.
  3. Open any .html or .js file in a code editor such as VS Code to change text, data and links.

Case and client pages

  • case-detail.html?id=CD-2026-0151 shows that case; without ?id= it shows CD-2026-0148. An unknown or badly formed number shows a "Case not found" message.
  • The data is in <script type="application/json" id="cd-data"> at the end of case-detail.html: each case with its hearings, documents, tasks, notes, timeline, time entries and invoices. assets/js/matters.js draws the page from it.
  • Add note, Upload, Add hearing, Add task, Log time and Close case update the case on the page straight away (in the page only). Ticking a task marks it done.
  • Deep links: case-detail.html?id=CD-2026-0148#cd-hearings opens the Hearings tab. Tab ids are cd-overview, cd-timeline, cd-hearings, cd-docs, cd-tasks, cd-notes, cd-billing, cd-activity.
  • client-detail.html?id=CL-102 works the same way with the cl-data JSON. invoice.html?no=INV-2026-0140 shows that invoice (&print=1 opens the print window).
  • New case: after the four steps, new-case.html opens Cases with the new matter at the top of the list (marked New). It is passed in the address and is not saved, so a reload removes it. To keep cases, post the form to your backend instead.

Calendar and cause list

  • The calendar shows four event types: hearings, court deadlines, tasks and meetings, each with its own colour. Use the chips to show or hide a type, the arrows to change month, and Agenda for a list view. Click a day to see it in the side panel; click an event for details.
  • calendar.html?date=2026-11-04 opens on that day; a missing or invalid date opens on the demo "today". Events are in the cal-data JSON at the end of the page.
  • The cause list shows one court day, grouped by court, numbered in calling order. The arrows skip weekends. cause-list.html?date=2026-11-04 opens that day. Print gives a clean A4 list without the menu. The Ready ticks are for the screen only.

Tasks board

Drag cards between To do, In progress and Done. On phones, or with the keyboard, use the card's ⋯ menu → Move to. Overdue cards have a red edge. The Court deadlines tab lists deadlines as a table.

Time and invoices

  • The timer counts while it runs; Save opens the Log time form with the hours (rounded to 0.1 h), case and description filled in. The timer keeps its time until the entry is saved, so Cancel loses nothing.
  • A new time entry shows the fee earner's hourly rate and the amount (rate × hours). A new draft invoice gets the next free number, adds tax at the firm rate, and only lists the chosen client's cases.
  • Invoices show professional fees, disbursements (expenses at cost, not taxed) and tax on fees. The balance due is the total less payments.
  • Statuses: Draft, Sent, Partly paid, Paid, and Overdue (an unpaid balance after the due date).

Firm, currency and tax

Settings → Firm changes the firm name, currency and tax rate. Every amount marked with data-money, every chart with a "$" prefix and the case, client and invoice pages follow the chosen currency at once. The tax rate is used for new invoices; existing invoices keep their saved tax.

The demo keeps these settings in the visitor's browser (localStorage casedesk-firm). The defaults are in the small script in the <head> of each page (window.CASEDESK).

Colours and logo

All colours are CSS variables at the top of assets/css/style.css. Change the brand variables to rebrand; the first two chart colours follow --primary and --accent. Dark mode has its own values in the [data-theme="dark"] block. The sidebar uses the --side-* variables.

:root {
  --primary: #1f3d64;        /* buttons, links, charts */
  --primary-strong: #152c4a; /* hover */
  --primary-soft: #e3eaf3;   /* light backgrounds */
  --accent: #a8803a;         /* brass highlights */
}

The logo is an inline SVG in each page (search for brand-mark) and a file in assets/img/logo.svg.

Fonts

Interface text uses Public Sans; page titles and large numbers use Newsreader; case numbers and amounts use JetBrains Mono. All three are included as .woff2 files and loaded with @font-face in section 1 of style.css. To use other fonts, change --font-ui, --font-display and --font-mono.

Dark mode

The moon button switches themes and the choice is remembered (casedesk-theme). On the first visit the template follows the device setting. Printing always uses the light colours.

Sidebar menu

The menu is the same block in every page: <nav class="nav">. Add a link with an icon, label and optional .count badge. The current page link has class="active". The panel button collapses the sidebar on desktop (casedesk-collapsed); on phones it slides in from the left.

Charts

Charts are SVG, drawn by charts.js from a JSON data-chart attribute. Types: line, area, bar, stacked, donut, spark. They redraw on resize and when the theme changes.

<div class="chart" data-chart='{"type":"bar","prefix":"$","suffix":"k","labels":["Sep","Oct"],
  "series":[{"name":"Billed","data":[15.7,26.2]}]}'></div>

Forms and validation

Add data-validate to a form. Fields with required, type="email", type="number" (with min/max/step), minlength or pattern are checked on submit (amount fields with data-amount accept 1250, 1,250 or 1,250.50 up to 999,999.99; a date with data-not-before="opened" cannot be earlier than the form's opened date), and the .error-text after the field is shown. Required checkboxes must be ticked. data-success shows a toast and data-redirect opens another page.

All forms are front-end only: nothing is sent to a server. A valid form fires a casedesk:submit event you can listen to.

Demo data and limits

  • Demo data — firm, people, clients, courts, judges and cases — is fictional. The demo "today" is Monday, 2 November 2026, so hearings and deadlines line up.
  • Where it lives: lists and tables are written in the HTML; case, client, invoice, calendar and cause-list data is in the JSON blocks described above; chart numbers are in each data-chart attribute.
  • Kept in this browser only (localStorage): casedesk-theme, casedesk-collapsed, casedesk-account (profile name and email) and casedesk-firm (currency, tax, firm name). Data that cannot be read is ignored and the defaults are used.
  • Not saved after a reload: rows, cards, notes, documents, hearings and tasks added with forms, and status changes.
  • Needs your backend: real sign-in, file storage (upload, preview, download), emails and reminders, invitations, and sharing data between users.

Connecting a backend

  • Case, client and invoice pages: return the same JSON shape from your API and put it in the cd-data, cl-data or inv-data block (server-side), or call CaseDeskMatters.renderCase(caseObject).
  • Calendar and cause list: fill the cal-data and cl-data JSON from your hearings, tasks and meetings.
  • Tables: render the <tr> rows from your database; search, filters, sorting, paging and export keep working.
  • Forms: listen for casedesk:submit on a form, or remove data-validate and post the form as usual.

Publishing

Upload the contents of the CaseDesk folder to any web host (cPanel, Netlify, Vercel, GitHub Pages). No server code is needed for the template itself.
